## Before → after, with tradeoffs

| Area | Before | Refined candidate |
| --- | --- | --- |
| Patient reading path | Separate shared-source prose, repeated discovery, retrieval list and a large relationship panel | One appointment anchor followed by one flat, scannable care index. Shared summaries have an honest short empty state; five secondary destinations remain explicit. |
| Repeated journeys | Find care appeared in global nav and a secondary CTA; available history had two entry links | Find care appears once in visible top Navigation A. Available history appears once. Summaries/follow-up, appointments, prescriptions and care relationships remain accessible. |
| Patient appointment | Complete details but extra explanatory copy around the primary CTA | Full doctor, date/month/year, explicit12h period, end time and clinic retained. A refined date band and one primary detail action carry hierarchy. Details still expose actual event zone/offset. |
| Doctor source access | Source jump led to the page tail | Native in-flow disclosure immediately before the writing plane. Closed label states allergy uncertainty. Open content repeats compact exact patient/date/24h range/IANA offset/current authority, then distinct source states. Close returns focus and scroll to its opener. |
| Doctor local tasks | Narrow task links were inside a collapsed menu, followed by a long stacked page | Three visible ordinary web links select Documentation, Follow-up or Review & close in place. Browser hash/back navigation works; current task is explicit. Unsaved textarea DOM/content survives task changes. No clinical command is implied. |
| Shared polish | More repeated blocks and explanatory padding | Intentional heading spacing, date emphasis, differentiated radii, restrained separators and stronger button hierarchy. Dark remains dark; Light keeps a white writing plane. Exact logo, icons and approved colors are retained. |

The matched390px [browser observations](evidence/refinement/before-after.json) distinguish page length from usability. Patient AR goes **1974→1296px** and EN **2081→1338px** in the same1200px-high browser. Doctor's initial Documentation view is shorter because follow-up/closure are accessible task views, not stacked below it; their content and consequences are retained. **The first editor begins slightly lower** (about38–42px in observed390px cases), because task/context controls are now explicit. The benefit is discoverability and nearby context, not a claimed faster first keystroke. Expanded context is still tall, but opens locally and closes predictably.

## Clinical, privacy and responsive boundaries

Patient sees own permitted shared information only. No private-note existence/counts, invented releases, signed history, clinical metrics or future Lab/AI capabilities are added. New care requests require patient permission and doctor acceptance; booking alone grants no clinical authority. Current `ClinicianPatientAssignment` remains the grant. Doctor access is a synthetic initial fixture, not a browser authorization check; current authority is required for each future read/write.

Private note signing does not share it. Patient summary, follow-up and irreversible close remain separate sources/actions. Save/sign/review/close affordances open explicit noncommitting preview dialogs; no success state, API, automatic retry, saved draft or released source is simulated. Local task changes hide/show existing DOM without discarding unsaved text. No PWA manifest, service worker, sensitive cache or offline write queue.

The event remains **12 November2026,13:00–13:30UTC**, **Africa/Cairo (UTC+02:00 on that date)**. Patient uses **3 مساءً /3pm**, explicit end period and full Gregorian date; details disclose zone/offset. Doctor uses **15:00–15:30** with zone visible. Repeated-hour/cross-zone overviews must expose offset; cross-midnight displays need both dates. No permanent Cairo offset or parser/storage/eligibility change.

Widths320/390/768/1024/1440 plus1920 and200% text are tested. Narrow task links wrap by intrinsic content width, not clipped labels. Context is normal flow, never a sticky overlay. Actual nodes move at the900px content threshold so source/visual/focus order agree; there is no duplicate source rail. Arabic remains independently authored RTL with zero heading tracking; Latin ranges and zone are isolated. Professional/action/source text stays16px at100%; all controls retain44px comfort.

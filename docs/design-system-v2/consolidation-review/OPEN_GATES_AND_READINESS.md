## Theme — OPEN owner decision, separate from two accepted review appearances

Recommend **System default + explicit System/Light/Dark override for the current in-memory session**, cleared on logout/account switch/new session. Apply the same initial rule to anonymous, personal authenticated and shared-clinic use; no account sync or persistent device preference in the first separately approved scope. This is a recommendation, not an implemented setting or a new final default. Existing gallery selectors and V1 locale/mode localStorage are not theme policy.

| Owner option | Benefits / tradeoffs and scope |
| --- | --- |
| T1 — recommended: system + session override | Smallest preference contract; shared terminals do not inherit another user's remembered choice. Override survives ordinary navigation only; reload/new session may return to system. Honor explicit override over OS changes until reset; do not infer theme from role or health data. |
| T2 — system + explicit browser/device persistence | Convenient on a personal device, but shared terminals may inherit it. Requires explicit remember/clear scope, logout/account-switch behavior, expiry/storage-failure and first-paint contract. Never store clinical identity/payload with theme; no implied cross-account sync. |
| T3 — explicit first-use choice, session only | Predictable clinic setup but adds a blocking choice and repeats it. Needs accessible recovery/default if no choice is made; do not block care tasks over appearance. |

Future SSR/FOUC acceptance: system-sensitive CSS/appropriate themed artwork must produce readable first paint before JS; manual override hydration cannot show a wrong-color flash or hydration mismatch. If persistence is later chosen, define a minimal non-sensitive initial preference signal and failure behavior explicitly; no cookie/storage/server API chosen here. Verify forced colors, high contrast, reduced motion, native zoom, actual screen-reader control names and cross-tab/account-switch behavior. System preference supports user needs but does not itself prove accessibility. Do not reuse Demo/session state to persist a theme.

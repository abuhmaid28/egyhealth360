## Visual judgment

The directions differ materially in spatial organization, navigation, source grouping and rhythm. Their distinction survives removal of hue:

| Aspect | Interval | Relay |
| --- | --- | --- |
| Patient attention | Large calendar/event plane, separate recommendation, retrieval below | Ruled bounded-source plane with event, independently attributed recommendation and shared summary; utility retrieval beside it on desktop |
| Clinical workspace | Private and patient-facing source planes side by side on wide desktop | Stacked source-purpose sections in one work plane, with a narrow context column |
| Perimeter and character | Open horizontal shell, squared pale mineral surfaces, larger date emphasis | Dark desktop rail, compact cobalt context band, denser continuous source plane |
| Main design risk | Date emphasis competes with the next task; simultaneous sources need explicit ownership | Familiar software rail conventions limit novelty; stacked sources add vertical travel |

The restrained palette, substantial whitespace, aligned source planes and bilingual type provide credible clinical proposals. They avoid invented health scores, charts, decorative medical imagery and repetitive metric-card dashboards. Relay's revised patient work plane improves the structural difference. These observations support a comparison; they do not establish exceptional originality, premium superiority, global uniqueness or legal design clearance. ## Clinical, Arabic and accessibility assessment

Normal revised Arabic full mobile screenshots show authored Egyptian Arabic, coherent RTL order, complete task/action captions and readable separated source purposes. Dates use Latin digits, named Gregorian months and chronological 24-hour intervals; Cairo's event offset is explicit. Proper names and time runs remain isolated rather than reversing chronology. Both Patient destinations and the Clinician Schedule/People in your care perimeter preserve accepted task hierarchy. Native Egyptian editorial review remains unperformed.

The two directions use the same facts within each role. Patient 09:00 and clinician 14:35 are explicitly different synthetic moments of the same visit, not contradictory simultaneous states. No age, sex, identifier, vital, medicine, lab result, diagnosis, dose or advice is invented. Unknown allergy is explicitly not equivalent to no known allergy.

Patient views expose separately released summary and recommendation content; no private-note/draft existence is hinted. A recommendation is explicitly not a booking and has no invented appointment association. Private signing, summary sharing, independent follow-up release and irreversible close retain distinct consequences. Closing explicitly saves/signs/releases nothing else. Booking grants no clinical authority; current assignment/privacy checks remain required. These are preservation of semantics in a specimen, not execution proof of backend policy.

Sampled rendered state screens distinguish read failure from an empty list, suppress patient/visit identity in uniform unavailable, and present uncertain signing without a new sign command or automatic retry. Original retained context and current authority are required for recovery. State fixture suppression is not a privacy boundary: the standalone source contains only synthetic literals.

Keyboard evidence includes real Tab entry to a visible skip link, Enter opening the native preview dialog, Escape dismissal and return to the triggering control. Separately captured scrolled summary/close controls have visible unobscured outlines and adjacent target context. Native semantic headings, labels and normal DOM order support the design. Computed contrast, target dimensions, overflow and text-range clipping measurements support inspection, but cannot certify complete accessibility. Native screen reader output, full keyboard traversal, browser zoom, real-device keyboards, text spacing, high-contrast modes and non-Chromium engines remain untested.

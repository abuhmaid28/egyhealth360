# Explicit audited design playbook — temporary pilot only

Mode: **EXPLICIT_AUDITED_PLAYBOOK_ONLY**. This file is deliberately read by the design agent. It is not a host-native Skill, install, activation, S1 behavioral test or Design System approval.

Adapted from the MIT Basic guidance of Next Level Builder, UI UX Pro Max, pinned in [upstream-lock.json](vendor/upstream-lock.json). Original selected rules: [basic-ux-excerpts.json](vendor/basic-ux-excerpts.json); [MIT notice](vendor/LICENSE). No upstream executable, Premium component, asset-generation feature, brand subskill or installer is imported.

1. Read owner scope and accepted UX/IA/content/Arabic/security first. Use actual repository stack for compatibility, but create plain isolated specimens. Never write application code.
2. Define two materially different composition hypotheses. Compare the same synthetic objects, facts and clinical states; vary hierarchy, spatial organization, typography scale and surface construction, not only hue. Use text wordmark only. No logo or final identity decision.
3. Apply Basic rows 36/39/40/41/43/45: readable contrast, semantic headings, named controls, DOM order matching visual order, visible labels and skip navigation. The CSV's custom tabindex example is not adopted; prefer native controls and normal DOM order.
4. Apply rows 9/22/23/28/66/100–102: reduced motion, visible focus, unobscured interaction, roomy mobile targets. Pilot policy is >=44 CSS px controls, >=48px key mobile actions; this is a design target, not a misstatement of WCAG's 24px criterion.
5. Apply rows 110/112/113/115: content-driven heights, bounded heading measures, wrapping and 320px plus 200% text checks. Essential identity/actions/consequences are never clipped. Row 116's nowrap suggestion yields to semantic wrapping on small Arabic screens.
6. Egyptian Arabic is authored as complete sentences, not English fragments. RTL uses logical properties and matching DOM order; isolate names, times, offsets and source identifiers. Never mirror chronology or clinical transitions. Retain local OFL fonts already in the repository; no external font requests.
7. Clinical status is text plus restrained visual treatment. Booking grants no clinical authority. Private note, patient summary, follow-up and close have separate consequences. Missing allergy evidence remains unknown. Patient never sees private/draft existence. No vitals, medication suggestions, results or AI filler.
8. Render every direction × role × language at desktop/mobile using free installed Chromium/Playwright. Add reflow, enlarged-text, focus and state evidence. Evaluate actual screenshots. Automated checks support, but never establish, visual quality.
9. A separate reviewer critiques the renders and records defects before revision. Designer may remedy, reviewer verifies. Reviewer does not choose final owner direction. Implementation role is dormant until later explicit owner approval of versioned specifications.

Its mandatory generator/persistence/implementation steps are intentionally excluded by this pilot's design-only and no-final-system scope.

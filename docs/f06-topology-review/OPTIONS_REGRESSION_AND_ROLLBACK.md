## 1. Concrete options and actual source support

**A1 — repair the default separate-container Compose route.** A future approved change could supply a credential-free service-reachable upstream such as `http://api:3001` while creating the Next build artifact, with explicit Docker build input → Compose build ownership → recorded image/manifest. Nonhosted [apiOrigin validation](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/apps/web/next.config.ts#L15) permits that origin syntactically; web-container DNS/reachability, build-time availability requirements and browser session forwarding are **UNVERIFIED**. Browser fetches must remain same-origin `/api/v1`, never browser calls to private `api`. Shared API/web/worker image construction must have one coherent input/digest; competing builds of one mutable tag can otherwise obscure which web artifact runs. An image containing a Compose-specific origin is not automatically portable to host processes or hosting.

**A2 — separately design runtime/server-proxy ownership.** An explicit runtime-resolved server proxy is a meaningful alternative to environment-specific images, but introduces more routing/error/forwarding/configuration behavior. Merely placing an environment variable in Compose runtime is not such a design or a verified fix for E13's built route. This larger subchoice needs its own bounded specification and allowlist before implementation; do not smuggle it into A1.

**B1 — validate a controlled host-namespace Live acceptance path.** Existing [real-browser harness74–89,145–163](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/scripts/test-ui-availability-real.mjs#L74) binds actual Nest API to ephemeral127.0.0.1, forwards through a loopback relay at127.0.0.1:3001, and starts built Next on127.0.0.1:3000. [Browser187–194](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/scripts/test-ui-availability-real.mjs#L187) uses `http://localhost:3000`, consistent with the configured browser Origin. Thus the default loopback rewrite can reach a relay/API **in that same namespace**. This is a source-supported candidate and historical E12 evidence, not fresh B validation. The harness creates disposable fixtures and performs real synthetic login/booking/document/close/replay operations: **write-capable, prohibited now**. It cannot be repurposed as a harmless health command without separately reviewing its scope.

For a later minimal B1 harness, explicitly isolate web/API/relay, disposable DB and port ownership; reuse current API factory/module composition and record any differences from the real entrypoint. [API main56](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/apps/api/src/main.ts#L56) itself binds0.0.0.0; do not describe arbitrary CLI API startup as loopback-only. A loopback factory harness or verified network isolation must prevent accidental external exposure. [Root dev17](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/package.json#L17) reads `.env` and [scripts/dev.mjs2–8](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/scripts/dev.mjs#L2) launches web, API, worker and watchers; it is not the minimal isolated test path. [compose.local.yaml](https://github.com/abuhmaid28/egyhealth360/blob/5355ae5b12bb86ed2c05f70fcadd77eadcd7bde3/compose.local.yaml) publishes DB loopback but does not replace Compose's persistent volume with proven disposable storage. No existing convenience command is an isolation attestation.

**B2 — separately validate an isolated same-origin reverse proxy.** A proxy could unify a nondefault web/API layout, but its upstream selection, headers, cookies, HTTPS and failure contract add moving parts. No proxy implementation/configuration is selected or verified. It must not weaken Origin/CORS/CSRF or become an arbitrary client-selected upstream.

## 6. Rollback boundaries and triggers

No rollback was rehearsed. A1 must atomically revert Docker build-origin plumbing, Compose inputs and the exact image/artifact/manifest; mutable tags or runtime variables alone cannot attest rollback. A2/B2 must also restore proxy routes, allowlisted headers, TLS and configuration versions. B1 must restore approved process/relay/port and artifact identity without accidentally using the broken Compose route or an unrelated local API.

Trigger rollback/stop on missing provenance, cross-service failure, invalid cookie/Origin handling, any private/wrong-patient leakage, unexpected clinical mutation/retry, incomplete required CI or resource-isolation failure. Retain a sanitized failing receipt. **Do not reload/remount/switch while a mutation, unknown outcome/key or unsaved clinical text is unresolved.** Drain operations; manually recover the identical key while current authority permits; obtain explicit unsaved-text disposition. If the key is lost, use separately approved server-source reconciliation, never invent a new key or persist clinical state for convenience. Transport rollback cannot un-sign/unrelease/reopen clinical facts, reverse migrations, recover volatile memory or alter a protected domain.

A revert to the original faulty main image preserves the known baseline but is not a working Live recovery. Before claiming safe recovery, identify a separately approved known-good candidate and rerun relevant R01–R11/R14 plus applicable E3 regressions under exact provenance. Owner acceptance and F06 closure remain distinct from reverting a patch.

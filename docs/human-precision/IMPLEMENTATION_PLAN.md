## Architecture fit

Retain Next.js/TypeScript, current REST adapters, session/authority boundaries, existing tests and current time/localization helpers. The current Patient component is large, while Clinician already separates orchestration/presentation; extract along approved task boundaries without a framework rewrite. `packages/ui` becomes documented presentational primitives only after API approval. Features own audience/source composition, adapters own service truth, server/database own actor/time/status. This isolated generator never becomes a product dependency.

Keep semantic tokens independent of React and any design vendor. Final CSS consumption should be generated and checked from versioned source; avoid independent parallel hard-coded palettes. Share identity and meaning, expose density as a constrained usage mode, and keep warnings/targets readable. A future dark theme must earn separate contrast, glare and task evidence; F does not authorize dark-by-default adoption.

## Useful next validation

Use synthetic task protocols: a patient identifies appointment vs follow-up recommendation, finds the released summary and explains who has care access; a clinician locates exact identity/allergy uncertainty, distinguishes private sign from release and understands close; pharmacy staff distinguish acceptance, recorded dispense and reversal. Compare H/P without a summed taste score. Record task mistakes and comprehension before claiming efficiency or preference. This sprint supplies visual/technical evidence only, not participant results.

Debt carried forward: independent owner visual review, native Egyptian editorial validation, screen-reader/browser/device testing, legal/recognition assessment for any final mark, complete final component APIs and versioning, Live integration outside this package and full longitudinal completeness. None is silently claimed solved by these static specimens.

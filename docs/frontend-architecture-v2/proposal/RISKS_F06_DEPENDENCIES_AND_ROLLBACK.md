### Ownership choices to examine later, not patches

A future owner-authorized investigation must choose **who supplies upstream routing at build time versus request/runtime**, and prove the generated artifact matches that choice. If a container-DNS destination is considered, its hostname/port must resolve from the **web container** on the intended network; browser callers must continue using same-origin `/api/v1`, not a private service hostname. An immutable image tied to a build origin and an explicitly runtime-resolved server proxy have different promotion/provenance risks; neither is selected or verified here. Do not assume adding a runtime variable changes Next's built rewrite or expose an upstream credential via `NEXT_PUBLIC_*`.

Keep browser cookie domain/path/Secure/SameSite/HttpOnly and server Origin/Fetch Metadata/CSRF checks intact. A reachable health URL is only stage1: forwarded Host/protocol, allowed browser Origin and same-origin Set-Cookie semantics must still match accepted auth contracts. Do not bypass checks with permissive CORS, disable CSRF, copy cookies between hosts or persist tokens. Routing belongs to app/deployment boundary under either A or B, never neutral UI.

## 4. Cross-cutting authority constraints

Backend current authority remains mandatory for reads, writes and replay; frontend buttons/role routes are not permissions. Patient owns permitted data only; current `ClinicianPatientAssignment` grants treating access. Booking, membership, public directory and authorship alone grant ZERO clinical authority. ADMIN has no blanket payload, impersonation, signing, assignment creation or break-glass shortcut. Private-note sign, summary sign/release, FollowUpIntent release and irreversible close remain independent; closing never signs/shares or certifies completeness.

Pharmacy requires exact current staff/session, active PHARMACY organization/membership and valid routed artifact with reduced-purpose history, never a patient-record browser. Acceptance is not dispensing; prescribed/dispensed is not confirmed actual use. Ending a clinician relationship does not itself cancel an otherwise valid routed pharmacy artifact. Patient/current clinician released-source visibility and staff access follow independent authority. Lab remains backend-first FUTURE/NOT LIVE; no fabricated results or mandatory second verifier. Missing evidence may remain UNCERTAIN; no invented clinical rule, diagnosis, treatment/dosage or TRUE_GAP.

Preserve wrong-patient payload/IDs/links/counts/pagination/replay/conflict suppression, immutable source/history, database/server actor/time/status, lock order and final current checks, canonical command keys, atomic fact/history/audit/result and no automatic clinical mutation retry. Generic children can still carry sensitive content despite clean imports: later tests must inspect rendered DOM/accessible labels/hidden nodes/counts, hydration/serialized props, URLs, errors and logs for leakage. No sensitive PWA cache, offline clinical writes or live credentials in browser storage/examples.

## 6. Rollback contract and verification design

**No rollback rehearsal executed here.** For either option, future pilot changes must be UI-only with an exact V1 parent/source manifest and atomic revertable commits. Preserve every route/semantics, original assets/evidence, domain/schema/migrations/API/OpenAPI, session/provider identity and existing command coordinators. B must revert package exports + consumer imports + CSS/import order + any separately approved toolchain/manifest edge together; reverting only one side can fail build/runtime. A must revert bridge + primitive/caller/CSS slice together and prove no global style leakage. Rollback cannot un-sign/unrelease/reopen a consultation, alter a server fact, reverse migrations or change protected domains.

Switch only at a defined safe boundary: **no in-flight mutation, explicit unsaved-text disposition and resolved uncertain command outcome before reload/provider remount/rollback**. Do not auto-save, auto-retry or persist clinical drafts/keys to make rollback convenient. If a lost committed response is unresolved, retain the existing adapter/provider and manual identical-key recovery while current authority permits; if the key has already been lost, stop the slice transition and use separately approved server-source reconciliation rather than inventing a new key or claiming memory recovery. Already committed facts remain authoritative. An approved reload may clear T1 by design and cannot promise volatile draft retention.

Later rehearsal: on an isolated authorized candidate, capture route/history/query/hash, locale/mode/theme, permitted patient/visit/source projections and command-map lifetime; complete manual uncertainty recovery, confirm zero pending commands and record consented unsaved disposition. Revert exact allowed UI commit(s), build/typecheck/test and repeat same V1 deep-link/Back/login/read/denial/no-store/CSRF checks. Compare authorized server facts/audit counts without exposing payloads; zero duplicate commands/facts or source/schema drift. Capture exact base/head/revert hashes and actual CI. No claim of recovering all user state from a static screenshot.

# NOVA and product application guidance

Static design guidance only. Use the selected identity consistently across Patient, Clinician, Pharmacy, Laboratory and Admin without changing accepted navigation, product capabilities, clinical permissions or density requirements.

[Arabic SVG](assets/nova-header-ar.svg) / [English SVG](assets/nova-header-en.svg) are exact PR #96 copies. Both are **fixed board-derived artwork**, not independently localized functional headers. They retain a matching illustrated arrangement, bilingual name and static notification/profile/menu artwork. They do not prove correct live RTL control order, accessible control behavior or notification semantics. The current Arabic wordmark fit issue remains pending. No full tagline is required inside a compact header.

## Desktop recommendation

Use a calm dark-teal header compatible with the identity; reserve gold for a restrained brand accent. Treat NOVA as the existing product visual direction, not another product name or a new logo. Keep the symbol/name visually unified and leave breathing space before navigation and utilities. Do not add all five workspace names or a second large NOVA wordmark merely to fill space. Role-specific context must stay subordinate to the single EgyHealth 360 identity.

Long bilingual/tagline lockups belong in a roomy introduction or brand presentation, not in a dense clinician working bar. A future compact name-plus-symbol composition needs owner review after DP01; this foundation does not manufacture a new SVG lockup. The preserved header specimens are reference applications, not final responsive component specifications.

## Arabic and English behavior guidance

English product header follows LTR task/navigation order. Arabic header should use RTL layout and independently authored natural Egyptian Arabic labels under accepted CD01–CD07. Align reading/utility order to the actual accepted product shell rather than mirroring the logo's geometry or relying on the fixed specimen. Keep the symbol itself unmirrored, preserve exact bilingual naming and isolate Latin digits/name runs. Product label translations, clinical terminology and accessible control names require parity; branding does not amend accepted IA.

## Mobile recommendation

At 320–430px use the unchanged standalone mark with separately legible product naming when space permits; omit taglines and defer secondary brand decoration before truncating core navigation. This describes later prototype behavior, not a new implemented compact lockup. Preserve enough room for essential utilities, readable task title and touch targets. Start controls at least 44×44 CSS px with visible keyboard focus, then validate against the actual product flow; these are recommendations, not tested production results.

For narrow or 200% text cases, allow a second row or a reduced decorative brand presence. Do not squeeze all board controls into one fixed-height bar, hide essential actions, mirror the care symbol, clip Arabic dots or use the full lockup as tiny text. Actual responsive AR/EN prototype validation, native browser zoom, screen reader interaction and physical device checks remain future gates. No homepage/navigation redesign or multi-portal implementation is authorized here.

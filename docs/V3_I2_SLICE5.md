## Exact technical contract before implementation

All targets/operationKey are canonical lowercase UUIDv4. All bodies are exact objects; all clinical text is human-entered, Unicode scalar bounded, no unpaired surrogates/C0/C1 controls except LF in narratives. No inference, HTML interpretation, silent trimming/truncation or automatic copying between document identities.

`POST /api/v1/consultations/{consultationId}/documents` creates a distinct document/root and immutable DRAFT version. Body: `{kind,content,patientInstructions,complaint,problems,diagnoses,allergyReview,operationKey}`. Optional complaint defaults null, problems/diagnoses default [], omitted allergyReview defaults `{state:"NOT_REVIEWED",items:[]}`. kind is PRIVATE_NOTE or PATIENT_SUMMARY; content max 8000 scalars; patientInstructions max 8000 (must be empty for PRIVATE_NOTE); complaint optional max 2000; problems/diagnoses each max 20 strings of max 500. Required content/patientInstructions are strings. allergyReview is exactly `{state,items}`; state REVIEWED_POSITIVE/REVIEWED_NO_KNOWN/UNKNOWN/NOT_REVIEWED. Each positive item exactly `{kind,text,reaction}`: kind ALLERGY/INTOLERANCE, text 1–500 scalars, reaction null or 1–500. At most 20; positive requires >=1, all other states require zero items. Genuine reviewer and DB time only for reviewed states. Structured fields are explicit parts of this document; only signing/releasing this summary releases those explicitly entered fields. No private-note copying.

`GET/HEAD /api/v1/consultations/{consultationId}/documents` lists exact current author's unrestricted documents, fixed page/pageSize. `GET/HEAD /api/v1/consultations/{consultationId}/documents/{documentId}` returns exact author's permitted version history. No generic document browser.

Commands beneath that exact document identity, all POST:

- `/sign`: PRIVATE_NOTE only, `{operationKey,expectedVersion}`; DRAFT -> SIGNED, never released.
- `/sign-release`: PATIENT_SUMMARY only, `{operationKey,expectedVersion}`; DRAFT -> SIGNED_RELEASED by explicit author command only.
- `/addenda` or `/corrections`: `{operationKey,expectedVersion,predecessorId,reason,content,patientInstructions,complaint,problems,diagnoses,allergyReview}` with same explicit content bounds, reason 1–1000. Creates immutable signed successor of current signed head, preserving source/root/predecessor/author and original release time. Corrections supersede previous effective content; addenda are identified as supplemental signed content. No overwrite or cross-patient move.
- `/privacy-restrictions`: `{operationKey,versionIds,reason}`; 1–100 unique exact affected versions of this document, reason 1–1000. Current author clinical write authority; independent append-only exact targets, no dynamic BP or cross-document propagation. Any explicitly targeted version makes that exact document lineage unsafe: the document is withheld from all ordinary reads/counts/replays. This is projection suppression, not insertion of new privacy targets or dynamic cross-document propagation; no forensic route. Successful response `{data:{restricted:true}}` contains no target IDs.

Mutation result and author detail: `{data:{id,consultationId,kind,versions,history:{page,pageSize,total}}}`, id is document root locator. Each author-visible version has `{id,version,kind,state,content,patientInstructions,complaint,problems,diagnoses,allergyReview,createdAt,signedAt,releasedAt,reason,predecessorId,effective}`. Allergy review adds reviewer public provider locator/reviewedAt (null when not reviewed). Internal actor/profile/patient/assignment/member IDs, operation/audit data never projected. Released versions omit the internal sequence number; draft predecessors are null. Privacy-unsafe roots are withheld entirely, so gaps/lineage IDs/counts cannot reveal restricted versions. Restricted original root is an independent document identity, never a private/draft version ID. Empty visible document has uniform 404.

`GET/HEAD /api/v1/me/summaries` and `/{summaryId}`: current ACTIVE PATIENT own SIGNED_RELEASED PATIENT_SUMMARY only, including permitted signed history. `GET/HEAD /api/v1/patients/{patientId}/summaries` and `/{summaryId}`: current ACTIVE CLINICIAN with own ACTIVE/null-ended assignment, same reduced released projection. Source clinic suspension does not hide released records from these viewers. No private/draft existence/count/reference widening. List envelope `{data:[document projections],meta:{page,pageSize,total}}`, fixed createdAt DESC,id ASC; collections include only the latest permitted version per document; exact detail pages bounded version history newest first (ascending within each page), one SQL snapshot for filtered items/count. Defaults page=1,pageSize=20; max page 10000,size100. No other query fields; exact detail permits only the same page/pageSize for version history.

## Authority, locking, replay and audit

Booking clinical authority ZERO. Current ClinicianPatientAssignment is the sole clinical grant; drafts/private are author-only plus current assignment. Writes additionally require exact current source clinic/member/provider/affiliation scope; public publication flags are not ongoing clinical entitlement. Patient/other clinician released reads use their own current authority; original authorship never bypasses assignment ending. ADMIN/LAB_STAFF/PHARMACY_STAFF denied.

New flows preserve compatible four M1 ROW EXCLUSIVE table intents -> sorted involved Users NO KEY UPDATE -> exact actor Session UPDATE/current checks -> actor ClinicianProfile SHARE -> ACTIVE Assignment SHARE -> PatientProfile SHARE -> directory-order clinic/provider locks for writes -> current settings SHARE -> patient then clinician namespaced transaction advisory locks -> Consultation/Encounter -> document root UPDATE -> version/privacy scope -> operation ledger -> final current authority -> version/history/operation + minimized audit -> final authority/expiry -> commit. No legacy runtime lock changes. READ COMMITTED, lock5s/statement10s/transaction30s; no automatic retry.

Actor+command+operationKey ledger retains canonical SHA256 payload and result document/version identities only, never cached payload authority. Same key/same command/payload has no duplicate source/version/audit; changed payload conflicts only after scope authorization. Rollback leaves key reusable. Replay retains its original version scope while reprojecting current effectivity and privacy; restricted affected result denies safely, never cached narrative. Every successful mutation appends one fixed DOCUMENT_DRAFTED / DOCUMENT_SIGNED / SUMMARY_RELEASED / DOCUMENT_ADDENDUM / DOCUMENT_CORRECTED / DOCUMENT_PRIVACY_RESTRICTED audit, exact entity, real actor, DB time, safeMetadata={}; audit failure rolls back everything.

HTTP retains strict bounded nested JSON/duplicate decoded keys per object/fatal UTF8, 16KiB, headers8192/URL2048, exact media/encoding, Origin/Fetch Metadata/session CSRF, no mutation query or Idempotency-Key, no-store/no ETag/Last-Modified/304, HEAD parity.
